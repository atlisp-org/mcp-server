## 二、P0 — 稳定与可验证性（0.5–1 天）

### P0-1 修复 main 红灯

- 将 `tests/resource.test.js` 的数量断言改为与 `RESOURCES` 定义联动，不再硬编码；
- 补 `atlisp://dwg/context-bundle` 的 URI/名称断言；
- 顺手加一条守卫：资源 URI 不得重复。

**验收**：`npm test` 全绿；新增断言在删除 context-bundle 时会失败。

### P0-2 覆盖率可观测

- `vitest.config.js` 增加 `coverage.reportOnFailure: true`；
- 增加 `coverage.thresholds`（lines 60 / functions 55 / branches 50）防止回退；
- CI 的 `npm test` 后跑一次 `npm run test:coverage`（或单独 job）。

**验收**：故意让一个用例失败时仍生成 coverage 报告；覆盖率低于阈值时 CI 失败。

### P0-3 发布前检查

- 在 `scripts/check-build.mjs` 或 CI 增加：资源数量、工具数量、版本号一致性检查；
- 更新 `docs/ROADMAP-2026Q4.md` 的完成状态（E1/F1/J1 打勾，G1 等顺延）。

## 三、P1 — 新能力（约 7–9 天）

### G1 长任务引擎（3–4 天）

**目标**：批量/导出类操作不再阻塞 Agent 的 `tools/call`，可轮询、可取消、可观测。

- 新增 `src/task-engine.js`
  - 任务状态机：`queued → running → succeeded / failed / cancelled`
  - 并发上限默认 2（CAD COM 不可重入，实际执行仍经命令队列串行）
  - 任务持久化到 `~/.atlisp/tasks.json`，完成后保留 24h，最多 200 条
  - 进度通过 `notifications/progress` 转发（复用 `tool-executor` 的 `notifyProgress`）
  - 取消在批次条目之间检查，不强行打断 CAD 命令
- 新增 `src/tools/task-tools.js` + `src/handlers/task-handlers.js`
  - `task_submit`（tool + args + 可选 timeout）
  - `task_status` / `task_list` / `task_cancel`
  - `task_result`（完成时返回与同步调用一致的结果）
- 首批接入：`batch_*`、`stream_export`（若存在）、`lint_project`、`dwg_kb_*` 扫描类
- 安全：`task_submit` 走与 `tools/call` 相同的参数校验、限速、审计、Undo 包装

**验收**：单元测试覆盖状态机/取消/并发上限/持久化恢复/TTL 清理；HTTP e2e 提交任务 → 轮询到成功 → 结果一致。

**风险**：任务与请求会话解耦后，`notifications/progress` 只能在提交它的会话内送达；跨会话查询进度需轮询 `task_status`（文档写明）。

### I1 elicitation 破坏性确认（2 天）

**目标**：对 `destructiveHint=true` 的工具，在客户端支持时请求用户确认。

- 新增 `src/elicitation.js`
  - 读取客户端 capabilities，不支持则保持现状（直接执行）
  - 模式：`ELICITATION_MODE=off|destructive|all`，默认 `off`（兼容红线）
  - 确认结果按 session + tool + 参数摘要缓存 5 分钟，避免连续确认
  - 用户拒绝返回 `USER_DECLINED` 错误（新增错误码）
- 在 `tool-executor.js` 的 `runToolCall` 入口接入，仅对 `DESTRUCTIVE_TOOLS` 生效
- 文档：README + `docs/` 写清支持矩阵与关闭方式

**验收**：单测覆盖「客户端支持/不支持/拒绝/接受/超时/缓存命中」；默认 off 时行为与当前完全一致。

**风险**：多数客户端尚未实现 elicitation；必须默认关闭，且确认失败不能阻断工具调用（降级为执行或按配置拒绝）。

### K1 错误上下文结构化（1–2 天）

**目标**：Agent 能从错误结果里直接知道「哪个工具、哪个 CAD 实例、卡在哪个阶段、下一步做什么」。

- `MCPError.details` 统一注入：`tool`、`instance`、`phase`（validate/connect/execute/undo）、`hint`、`suggestedTools`、`correlationId`
- `mcpErrorResponse` 文本保持人类可读；同时返回 `structuredContent`（错误对象），便于 Agent 程序化处理
- 参数摘要脱敏：只保留键名与类型，长字符串截断（≤120 字符）
- 审计日志同步写入 `correlationId`，便于和服务端日志对齐
- 新增错误码：`USER_DECLINED`、`TASK_NOT_FOUND`、`TASK_CANCELLED`

**验收**：单测校验字段齐全、敏感参数不落盘、旧文本格式仍可被现有用例匹配。

## 四、P2 — 增强（约 5–6 天）

### H1 sampling 补完（2 天）

- `stream: true` 支持（SSE 解析，聚合为最终文本；客户端不需要流式时仍返回完整结果）
- 降级链可配置：`SAMPLING_PROVIDERS=vllm,deepseek,openai`，逐个尝试，全失败回落 `echo`
- token 用量与估算成本写入 `metrics.js`（输入/输出 token、按 provider 计价）
- 单测 mock fetch：成功、4xx、超时、降级、全部失败

### L1 启动 profiling / 懒加载（1 天）

- 增加 `--profile-startup`（打印各模块 import 耗时后退出）
- 对重模块做动态 import：`dwg-kb-handlers`、`peer-*`、`lint-analyzer`、`sampling`
- 目标：`node src/atlisp-mcp.js --help` 冷启动 ≤ 400ms（当前依赖链 742ms）

### M1 OTel / Grafana 模板（1–2 天）

- 现有 Prometheus exporter 已具备；补齐 `deploy/grafana/atlisp-mcp-dashboard.json`
- 看板面板：工具耗时 P50/P95、错误率、CAD 忙等时长、peer 转发成功率、任务队列深度
- `docs/observability.md`：指标清单、抓取配置、告警建议

## 七、兼容性红线

- `TOOL_PROFILE` 默认 `full`，现有工具发现行为不变；新增工具必须带 `category` 与只读/破坏性注解
- 协议保持 2025-11-25 主版本 + 2024-11-05 回退
- `ELICITATION_MODE` 默认 `off`；I1 上线不改变任何现有调用行为
- G1 新增工具不替换现有同步工具；批量工具默认仍同步执行
- 错误响应保持 `content` 文本兼容，`structuredContent` 为增量字段
- 每个里程碑：`npm run lint`（0 问题）+ `npm test` 全绿 + `npm run build` 成功

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| CAD COM 不可重入，任务并发导致 `No open document` | 任务引擎并发上限 2，实际 CAD 调用仍走单一命令队列；e2e 验证 |
| elicitation 客户端支持率低 | 默认 off；不支持时降级为当前行为，不阻断 |
| 覆盖率统计在失败时不产出 | P0-2 修 `reportOnFailure`，CI 单独跑 coverage |
| 长任务持久化文件损坏 | 写入用临时文件 + rename；读取失败回退空列表并记日志 |
| sampling 流式解析差异（OpenAI/DeepSeek/vLLM） | 按 `data: [DONE]` 终止，忽略未知事件；provider 各自单测 |
| 懒加载破坏打包（esbuild 动态 import） | 沿用「字面量目录 + 变量文件名」模板字符串写法；打包后 e2e 冒烟 |
